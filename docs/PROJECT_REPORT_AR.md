## 1) الملخص التنفيذي

**SchoolPlatform** نظام إدارة مدرسية متكامل يغطي الدورة التشغيلية للمدرسة من أول تسجيل طالب حتى
تحصيل آخر قسط: الهيكل الإداري (مؤسسات، صفوف، مواد)، شؤون الطلاب والمعلمين وأولياء الأمور،
الحضور اليومي، الدرجات والامتحانات، الرسوم والمدفوعات، الإشعارات، ومساعد ذكي يحلّل الملفات
ويجيب عن الأسئلة — إضافة إلى ست بوابات دخول منفصلة حسب الدور.

المنتج **مكتمل وظيفياً وجاهز للتشغيل**، وليس نموذجاً أولياً: يعمل الآن على الإنترنت، لديه
قاعدة بيانات سحابية، بريد إلكتروني فعّال لاستعادة كلمة المرور، **313 اختباراً آلياً ناجحاً**،
نسخ احتياطي، مراقبة دورية، ونشر تلقائي.

**القيمة الأساسية للمشتري:** نظام جاهز بهوية عربية، مبني على تقنية مستقرة وواسعة الانتشار
(Django)، بكود منظم وقابل للصيانة والتوسعة، وبتكلفة تشغيل شبه صفرية في المرحلة الحالية.

## 2) المشكلة التي يحلّها المنتج

المدارس الأهلية والمعاهد والمراكز التعليمية في المنطقة تدير عملها اليومي عبر مزيج من
الدفاتر الورقية وملفات Excel ورسائل WhatsApp، ما ينتج عنه:

| المشكلة | الأثر |
|---|---|
| سجلات حضور ورقية | فقدان السجل، صعوبة إثبات الغياب، لا إحصاءات |
| درجات موزعة في ملفات متعددة | أخطاء حسابية، تأخير في إعلان النتائج، لا مقارنة بين المواد |
| رسوم تُحصَّل يدوياً | تسرّب مالي، عدم وضوح المتبقي على كل طالب، لا إيصالات |
| لا تواصل منظم مع ولي الأمر | شكاوى متكررة، انعدام الشفافية |
| بيانات مكررة بين الإدارة والمعلمين | هدر وقت، تعارض في الأرقام |
| لا صلاحيات محددة | أي موظف يرى كل شيء، لا أثر تدقيق |

**SchoolPlatform** يجمع ذلك كله في نظام واحد، بقاعدة بيانات واحدة، وصلاحيات دقيقة،
وسجل تدقيق لكل عملية حساسة.

## 3) الأهداف

### 3.1 أهداف تشغيلية
1. رقمنة الحضور والدرجات والرسوم بالكامل.
2. تقليل الوقت المستغرق في الأعمال الإدارية المتكررة (كشف الحضور، حساب المعدلات، متابعة المتأخرات).
3. توحيد مصدر الحقيقة: رقم واحد للطالب، للمادة، للمتبقي المالي.
4. تمكين الإدارة من رؤية مؤشرات المدرسة لحظياً بدل انتظار تقارير نهاية الشهر.

### 3.2 أهداف تعليمية
1. إعطاء الطالب صورة واضحة عن أدائه ومعدله ونسبة حضوره.
2. إعطاء ولي الأمر وصولاً مباشراً إلى درجات أبنائه وحضورهم ورسومهم دون وسيط.
3. تمكين المعلم من إدخال الحضور والدرجات في دقائق من هاتفه.

### 3.3 أهداف تجارية (من منظور المشتري)
1. منتج قابل للتسويق كخدمة اشتراك شهري/سنوي للمدارس.
2. بنية متعددة المؤسسات (Multi-tenant) تسمح بخدمة عدة مدارس من نسخة واحدة.
3. تكلفة تشغيل منخفضة تسمح بهامش ربح مرتفع في المرحلة الأولى.
4. كود مملوك بالكامل وقابل للتخصيص باسم العميل.

## 4) المستخدمون والأدوار

النظام يفرض الفصل بين الأدوار على مستوى الخادم (Decorators + Middleware)، لا على مستوى
إخفاء الأزرار فقط. أي محاولة وصول مباشرة إلى رابط غير مصرّح به تُرجع **403**.

| الدور | البادئة | ماذا يستطيع |
|---|---|---|
| **مدير النظام** (System Admin) | `SYS` | كل شيء: إنشاء المؤسسات، إدارة كل المستخدمين، رؤية إحصاءات النظام كله |
| **المدير** (Manager) | `ADM` | إدارة مؤسسته: الطلاب، المعلمون، أولياء الأمور، الصفوف، المواد، الدرجات، الحضور، الرسوم |
| **مساعد المدير** (Assistant Manager) | `ASM` | نفس صلاحيات المدير داخل مؤسسته (بدون إنشاء مؤسسات) |
| **المعلم** (Teacher) | `TCH` | طلابه، حضور مواده، إدخال درجات مواده فقط |
| **الطالب** (Student) | `STU` | لوحته، مواده، درجاته، حضوره، ملفه، رسومه |
| **ولي الأمر** (Parent) | `PAR` | أبناؤه، درجاتهم، حضورهم، رسومهم |

### 4.1 خصائص الهوية
- **الدخول بكود وليس باسم مستخدم**: كل مستخدم يحصل على كود فريد تلقائي (مثل `STU000042`)،
  والكود يُعاد توليده تلقائياً إذا تغيّر دور المستخدم.
- **إجبار تغيير كلمة المرور** عند أول دخول (Middleware يمنع أي صفحة أخرى حتى التغيير).
- **إجبار استكمال الملف** للطالب/المعلم/ولي الأمر قبل استخدام النظام.
- **صورة شخصية** اختيارية: تُصغَّر إلى 800×800، تُصحَّح دورتها من بيانات EXIF، وتُحوَّل إلى JPEG.

## 5) الميزات بالتفصيل

### 5.1 المؤسسات والصفوف والمواد

| الميزة | التفاصيل |
|---|---|
| مؤسسات متعددة | كل مدرسة/معهد/مركز سجل مستقل بشعاره وألوانه وبياناته |
| كود مدير المؤسسة | `MGR-<الاسم المختصر>` يُولَّد تلقائياً وبشكل فريد |
| تبديل المؤسسة | المدير الذي يدير أكثر من مدرسة ينتقل بينها من شاشة اختيار؛ الاختيار يُخزَّن في الجلسة |
| الصفوف | المرحلة (ابتدائي/متوسط/إعدادي)، الصف، المستوى، السنة الدراسية |
| قيد فريد | لا يمكن تكرار (المؤسسة + الاسم + المستوى + السنة) |
| المواد | مادة مرتبطة بمؤسسة وصف ومعلّم اختياري |
| عزل البيانات | كل استعلام إداري محصور في المؤسسة الحالية — لا تسرّب بين المدارس |

### 5.2 شؤون الطلاب

- إضافة طالب مفرد أو **استيراد مئات الطلاب من ملف Excel**.
- الاستيراد يكتشف صف العناوين تلقائياً من أول 10 صفوف، ويفهم العناوين بالعربية والإنجليزية
  (`الاسم الأول`, `first name`, `رقم الطالب`, `student code`, `الجنس`, `gender` …).
- لكل طالب مستورد: **كود طالب** (`S000001`…) و**حساب دخول** و**كلمة مرور عشوائية قوية**
  (12 خانة) تُعرض له مرة واحدة وتُطبع في PDF، مع إجبار التغيير عند أول دخول.
- كشف التكرار بالاسم الكامل المطبَّع، وتجاوز المكرر بدل إنشاء حساب مزدوج.
- تقرير نتيجة الاستيراد: كم أُنشئ، كم تُخطّي، وما الأخطاء سطراً بسطر.

### 5.3 شؤون المعلمين وأولياء الأمور

- ملف معلم: الرقم الوظيفي، التخصص، الهاتف، تاريخ التعيين.
- ملف ولي أمر: صلة القرابة + ربط بأي عدد من الأبناء.
- ربط ولي الأمر بأبنائه يُستخدم لتحديد مدرسته تلقائياً (عبر ابنه) ولمنع رؤية أبناء غيره.

### 5.4 الحضور

| القدرة | التفاصيل |
|---|---|
| الحالات | حاضر / غائب / متأخر / مُبرَّر |
| جلسة حضور جماعية | المدير أو مساعد المدير أو المعلم يفتح جلسة (صف + مادة + تاريخ) ويسجّل الكل في شاشة واحدة |
| زر «الجميع حاضر» | تعبئة كل الطلاب بحالة «حاضر» بضغطة واحدة ثم تعديل الحالات الاستثنائية |
| منع التكرار | لا تُقبل جلستان لنفس (الصف + المادة + التاريخ) |
| منع التعارض | قيد فريد لكل (طالب + مادة + تاريخ) |
| حضور المعلم | المعلم يرى مواده فقط، والتاريخ يوم اليوم، ويُحدَّث السجل بدل تكراره |
| التقويم الشهري | شبكة شهرية بعدّادات لكل حالة، يراها كل دور بنطاقه (الطالب نفسه، ولي الأمر أبناءه) |
| الحساب التلقائي | نسبة الحضور = الحاضر ÷ الإجمالي، تظهر في لوحات الطالب وولي الأمر والمدير |

### 5.5 الدرجات والامتحانات

- إدخال درجة لكل (طالب + مادة + اسم امتحان) مع تاريخ الامتحان وملاحظة.
- **تحقق صارم**: لا درجة سالبة، لا درجة أعلى من العلامة القصوى، والعلامة القصوى > 0.
- قيد فريد يمنع تكرار نفس الامتحان للطالب نفسه في المادة نفسها.
- **المعلم مقيّد بمواده فقط**: أي محاولة لإدخال درجة في مادة ليست له تُرفض على الخادم (404).
- حساب تلقائي: متوسط المادة، النسبة المئوية، المعدل العام لكل طالب، ومعدل المدرسة.
- عرض أحدث الدرجات مع نسبة كل درجة، ومقارنة المواد في لوحة الطالب.

### 5.6 الرسوم والمدفوعات (النواة المالية)

| الكيان | المعنى |
|---|---|
| **نوع الرسم** (FeeType) | بند مالي: تسجيل، كتب، نقل… بمبلغ بالدينار وقابل للتفعيل/الإيقاف |
| **رسم الطالب** (StudentFee) | استحقاق على طالب محدد في سنة دراسية، مع المبلغ المدفوع |
| **الدفعة** (Payment) | سداد فعلي: نقدي / بطاقة / حوالة بنكية، مع من سجّله |

- **تحصيل جماعي**: توليد استحقاق لكل طلاب صف كامل بضغطة (بدون تكرار الموجود مسبقاً).
- **قفل الدفع (Payment lock)**: تسجيل الدفعة يتم داخل معاملة قاعدة بيانات مع `SELECT … FOR UPDATE`،
  ويُرفض أي مبلغ يتجاوز المتبقي — يمنع الدفع المزدوج والتلاعب عند تعدد الموظفين.
- **عكس الدفعة**: حذف دفعة يعيد المتبقي تلقائياً، مع أرضية صفر.
- **حماية الحذف**: لا يُحذف استحقاق له دفعات، ونوع الرسم المستخدَم يُعطَّل بدل حذفه.
- **كشف مديونيات**: لكل طالب (المستحق / المدفوع / المتبقي) مع بحث وترقيم.
- **إيصال قابل للطباعة** لكل دفعة، و**قائمة أسعار الرسوم PDF**.
- **صفحة «رسومي»**: الطالب يرى رسومه، وولي الأمر رسوم أبنائه.

> ملاحظة مهمة للمشتري: «بطاقة» هنا تعني **طريقة سداد مسجّلة يدوياً**، وليست بوابة دفع
> إلكترونية. ربط بوابة دفع (ZainCash / Qi Card / Stripe) بند ضمن خارطة الطريق.

### 5.7 الإشعارات

- إشعارات داخل المنصة (جرس + عدّاد غير المقروء) لكل عملية تخص المستخدم.
- 11 نوعاً: طالب، معلم، ولي أمر، صف، مادة، درجة، حضور، مالية، إعلان، مؤسسة، نظام.
- تُنشأ تلقائياً عند: إنشاء/تعديل/حذف أي كيان، تسجيل حضور، إدخال درجة، استلام دفعة، استيراد طلاب.
- «تحديد الكل كمقروء»، وانتقال مباشر إلى الكيان المعني من الإشعار.
- دعم بريد اختياري موجود في الكود لكنه **معطّل افتراضياً** (انظر القيود).

### 5.8 المساعد الذكي

| القدرة | التفاصيل |
|---|---|
| محادثة عربية | واجهة دردشة كاملة مع حفظ المحادثات (آخر 10 محادثات لكل مستخدم) |
| نماذج خارجية | OpenRouter بموديل مجاني افتراضي + موديلان احتياطيان وتسلسل تراجع تلقائي |
| تحليل الملفات | رفع PDF / Word / Excel / نص / CSV / صور (حتى 10 ملفات، 20MB للملف) |
| استخراج النص | قراءة محتوى PDF و Word و Excel و CSV لعرضه على النموذج |
| مهام جاهزة | تلخيص، تحليل، سؤال وجواب عن الملف |
| تقرير PDF | توليد تقرير عربي (RTL) عن الملفات المرفقة بالخط والشعار |
| سلامة المحتوى | بوابة أمان على الخادم تمنع الأسئلة الضارّة قبل إرسالها للنموذج |
| شخصية المساعد | «هدى» أو «ريّان» حسب جنس المستخدم |
| العمل بدون إنترنت | عند غياب مفتاح API أو فشل المزوّد، يجيب المساعد محلياً بدل أن يتعطّل |
| عزل | محادثات كل مستخدم خاصة به |

### 5.9 لوحات المعلومات والتقارير

| اللوحة | ما تعرضه |
|---|---|
| مدير النظام | إجماليات المستخدمين/المؤسسات/الطلاب/المعلمين، توزيع الأدوار، أحدث المستخدمين والمؤسسات |
| المدير | عدد الطلاب والمعلمين والصفوف والمواد، حضور اليوم، معدل الدرجات، إجمالي الرسوم/المدفوع/المتبقي، اتجاه الحضور 7 أيام، متوسط المواد، الطلاب المعرّضون للخطر، أحدث السجلات |
| المعلم | مواده، صفوفه، عدد طلابه، عدد سجلات الحضور والدرجات |
| الطالب | أحدث 8 درجات بنسبها، أحدث 5 سجلات حضور، متوسط كل مادة، المعدل العام والنسبة، نسبة الحضور |
| ولي الأمر | لكل ابن: أحدث الدرجات، المعدل، نسبة الحضور، عدد المواد |

**تصدير PDF:** بيانات دخول الطلاب المستوردين، قائمة أسعار الرسوم، تقرير المساعد.
**طباعة:** إيصال دفع.
> لا يوجد حالياً تصدير Excel/CSV للتقارير (بند في خارطة الطريق).

### 5.10 تجربة الاستخدام

- **تطبيق ويب قابل للتثبيت (PWA)**: يُثبَّت على الهاتف أو الكمبيوتر بأيقونة وشاشة كاملة بلا متاجر.
- **وضع ليلي** كامل مع تذكّر الاختيار ومنع الوميض عند التحميل.
- **عربي RTL افتراضياً** بخط Cairo، وتبديل فوري للإنجليزية بخط Inter.
- **متصفح الجوال أولاً**: قوائم منسدلة، جداول متجاوبة، أزرار كبيرة.
- صفحات خطأ مخصصة (400/403/404/500) بالعربية.
- بحث وترقيم في كل القوائم الطويلة.

## 6) كيف تعمل المنصة

### 6.1 المكدس التقني

| الطبقة | التقنية |
|---|---|
| اللغة | Python 3.12+ |
| الإطار | Django 6.0 (MVT) |
| قاعدة البيانات | PostgreSQL 16 (Neon) في الإنتاج — SQLite للتطوير فقط |

| الملفات الثابتة | WhiteNoise + CDN الخاص بـ Vercel |
| ملفات المستخدمين | قاعدة البيانات (DatabaseStorage) أو أي S3 متوافق |
| القوالب | Django Templates + Bootstrap 5 + CSS مخصص |
| JavaScript | Vanilla JS (بلا أطر ثقيلة) |
| Excel | openpyxl |
| الصور | Pillow (تصغير، EXIF، تحويل) |
| PDF عربي | reportlab + arabic-reshaper + python-bidi |
| قراءة PDF/Word | pypdf + python-docx |
| البريد | SMTP (Brevo) |
| الذكاء الاصطناعي | OpenRouter API + منطق محلي احتياطي |
| الترجمة | Django i18n — 664 رسالة |

### 6.3 مسار الطلب داخل النظام

```
طلب المتصفح
   ↓
SecurityMiddleware → HTTPS إجباري، HSTS، حماية XSS/Clickjacking
   ↓
WhiteNoise → يقدّم CSS/JS من نفس الخادم بسرعة
   ↓
Session / Locale → اللغة (عربي/إنجليزي)
   ↓
CsrfView → حماية CSRF لكل نموذج
   ↓
Authentication → من المستخدم؟
   ↓
ForcePasswordChange → هل يجب تغيير كلمة المرور؟ حوّله
   ↓
RequireRoleProfile → هل ملفه (طالب/معلم/ولي أمر) مكتمل؟
   ↓
TenantMiddleware → ما المؤسسة الحالية؟ (من الجلسة أو من الملف)
   ↓
role_required(*) → هل دوره يسمح بهذا الرابط؟ وإلا 403
   ↓
View → Service → ORM → PostgreSQL
   ↓
NotificationService (إشعار الأطراف) + AuditLog (إن كانت عملية حساسة)
   ↓
HTML أو JSON أو PDF
```

### 6.4 تعدد المؤسسات (Multi-tenancy)

- المنصة تخدم عدة مدارس في قاعدة بيانات واحدة، والفصل يتم على مستوى الطلب.
- **مدير النظام** يرى كل المؤسسات ويختار أيّها.
- **المدير/المساعد** يرى فقط المؤسسات المرتبطة به، ويبدّل بينها بجلسة محفوظة.
- **الطالب/المعلم/ولي الأمر** مثبَّتون على مؤسستهم من ملفهم الشخصي — لا يمكنهم التبديل.
- كل استعلامات القوائم والتفاصيل مقيَّدة بالمؤسسة الحالية، والاختبارات تتحقق من عدم تسرّب البيانات.

### 6.5 دورة حياة الطالب (مثال كامل)

1. المدير ينشئ الصف والمادة ويعيّن المعلم.
2. يضيف الطلاب يدوياً أو يستوردهم من Excel → تُنشأ الحسابات وكلمات المرور.
3. يطبع بيانات الدخول ويسلّمها للطلاب.
4. الطالب يدخل بكوده، يُطلب منه تغيير كلمة المرور، ثم يكمل ملفه.
5. المعلم يسجّل الحضور اليومي من هاتفه.
6. المعلم يُدخل درجات الامتحان.
7. ولي الأمر يفتح لوحته فيرى الغياب والدرجة والمعدل.
8. الإدارة تولّد استحقاق الرسوم لكل الصف، وتسجّل الدفعات، وتطبع الإيصال.
9. لوحة المدير تُظهر في نهاية اليوم: نسبة الحضور، معدل الدرجات، المتأخرات المالية.

## 12) خارطة الطريق المقترحة

### المرحلة الأولى (شهر واحد) — «جاهز للبيع»
1. كشوف درجات وشهادات PDF رسمية بالعربية.
2. تصدير Excel/CSV لكل القوائم والتقارير.
3. جدول الحصص الأسبوعي وربطه بالحضور.
4. واجهة لعرض سجل التدقيق مع بحث وتصفية.
5. تفعيل إشعارات البريد وضبطها لكل نوع.
6. جدولة النسخ الاحتياطي تلقائياً.

### المرحلة الثانية (شهران) — «جاهز للمدارس الكبيرة»
1. بوابة دفع محلية (ZainCash / Qi Card) + ربطها بالاستحقاق.
2. فواتير مرقّمة رسمية + كشف حساب لولي الأمر.
3. حصص المساعد الذكي + لوحة استهلاك.
4. تقارير تحليلية متقدمة (اتجاه الأداء، مقارنة الصفوف، إنذار مبكر للتسرب).
5. إدارة سنوات دراسية وأرشفة.
6. صلاحيات دقيقة قابلة للتخصيص (Role Builder).

### المرحلة الثالثة (3–6 أشهر) — «منتج SaaS متكامل»
1. تسجيل مدارس ذاتي + اشتراكات وفوترة.
2. تطبيق من المتاجر (غلاف PWA أو React Native).
3. رسائل SMS/WhatsApp لأولياء الأمور.
4. واجهة API للتكامل مع الأنظمة الحكومية والمحاسبية.
5. لوحة تحكم مركزية لمزوّد الخدمة (كل المدارس في شاشة واحدة).

## 16) نموذج التسليم التجاري (خيارات للمشتري)

| الخيار | ما يعنيه | لمن يناسب |
|---|---|---|
| **نقل ملكية كاملة** | الكود والحسابات والملكية الفكرية تنتقل للمشتري | شركة تريد بناء منتجها الخاص |
| **ترخيص استخدام** | المشتري يستخدم ويعدّل، والبائع يحتفظ بالملكية الأصلية | مدرسة أو مشغّل صغير |
| **استضافة مُدارة (SaaS)** | البائع يشغّل المنصة مقابل اشتراك شهري لكل مدرسة | من لا يريد فريقاً تقنياً |
| **بيع بالأصل + دعم** | نقل الملكية + عقد صيانة سنوي | الشركات التي تريد ضمان استمرارية |

**الترخيص الحالي:** المستودع لا يحتوي ملف ترخيص مفتوح المصدر، أي أن الحقوق محفوظة للبائع
حتى يتم الاتفاق الكتابي — وهذا يمنح المشتري مرونة في التفاوض على نقل ملكية حصرية.

**التزامات مستحقة على المشتري بعد التسليم:**
- تجديد مفاتيح الخدمات (Vercel / Neon / Brevo) باسمه.
- إبقاء الاختبارات تعمل مع أي تعديل.
- الالتزام بسياسة الخصوصية عند جمع بيانات القُصّر (موافقة ولي الأمر، حد أدنى من البيانات، حذف عند الطلب).
